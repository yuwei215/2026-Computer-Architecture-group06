## A. 語意規格(負責:羅允辰)

### THRESHOLD
- 語意(公式):
  > 提示:照 HOMEWORK 第六節寫公式,並用一句話說明「比較是有號還是無號」、「哪一個運算元是門檻」。
- 運算元與定義域:
  > 提示:`rs1`、`rs2` 各是幾位元?被當成有號還是無號?最小值、最大值各是多少(寫十進位與十六進位)?
- 結果範圍:
  > 提示:`rd` 可能出現哪些值?有沒有第三種可能?
- 邊界條件與溢位處理:
  > 提示 1:這個指令只做「比較」,沒有做加減,想一想會不會溢位。
  > 提示 2:`rs1 == rs2` 時結果是什麼?(對照官方測資 (5,5))
  > 提示 3:如果 `rd` 是 `x0`,寫進去的值會怎樣?(查 RISC-V 對 `x0` 的規定)
  > 提示 4:如果用無號比較,哪些輸入會錯?可引用 CP1 的 `tests/signed_vs_unsigned.c` 與 CP2 `rv32im/count_result.md` 的 `bgeu` 對照結果。
- 測試向量(至少 3 組,含 1 組邊界值):

  | # | rs1 | rs2 | rd(預期) | 說明 |
  |---|---:|---:|---:|---|
  | 1 | | | | 待填 |
  | 2 | | | | 待填 |
  | 3 | | | | 待填(邊界值) |

  > 提示:官方 3 組是 (5,5)、(4,5)、(-1,0);邊界值可從 `tests/threshold_tests.md` 的 ✱ 組挑,或用 CP2 量過的 (2147483647, -2147483648)。預期值要自己手算,寫出為什麼。
- 對應的 RV32IM baseline 片段與指令數:
  > 提示:片段直接引用 `rv32im/threshold_branch.s`(簡嘉佑),指令數引用 `rv32im/count_result.md`,要寫「靜態幾條、動態幾條、條件分支幾條、用什麼工具與版本量的」。

## B. 機器碼與欄位說明(負責:簡嘉佑)

### 欄位格式(HOMEWORK 第四節,R-type、custom-0)

```
31      25 24   20 19   15 14  12 11    7 6       0
+----------+-------+-------+------+-------+---------+
|  funct7  |  rs2  |  rs1  |funct3|  rd   | 0001011 |
+----------+-------+-------+------+-------+---------+
```

| 欄位 | 位元 | 值 | 說明 |
|---|---|---|---|
| `funct7` | [31:25] | `0000000` | **助教指定** |
| `rs2` | [24:20] | 暫存器編號(5 位元) | 門檻 |
| `rs1` | [19:15] | 暫存器編號(5 位元) | 輸入 |
| `funct3` | [14:12] | `000` | **助教指定** |
| `rd` | [11:7] | 暫存器編號(5 位元) | 結果(0 或 255) |
| `opcode` | [6:0] | `0001011` | custom-0(0x0B),HOMEWORK 第四節規定 |

### 機器碼範例(手算)

暫存器編號:`a0` = `x10` = `01010`、`a1` = `x11` = `01011`;`t0` = `x5` = `00101`、`t1` = `x6` = `00110`、`t2` = `x7` = `00111`。

| 組合語言 | funct7 | rs2 | rs1 | funct3 | rd | opcode | 十六進位 |
|---|---|---|---|---|---|---|---|
| `threshold a0, a0, a1` | `0000000` | `01011` | `01010` | `000` | `01010` | `0001011` | `0x00B5050B` |
| `threshold t0, t1, t2` | `0000000` | `00111` | `00110` | `000` | `00101` | `0001011` | `0x0073028B` |
| (對照)`add a0, a0, a1` | `0000000` | `01011` | `01010` | `000` | `01010` | `0110011` | `0x00B50533` |

計算過程(以 `threshold a0, a0, a1` 為例):

```
0000000 01011 01010 000 01010 0001011    (funct7|rs2|rs1|funct3|rd|opcode)
0000 0000 1011 0101 0000 0101 0000 1011  (每 4 位元一組)
   0    0    B    5    0    5    0    B  → 0x00B5050B
```

`threshold t0, t1, t2`:

```
0000000 00111 00110 000 00101 0001011
0000 0000 0111 0011 0000 0010 1000 1011
   0    0    7    3    0    2    8    B  → 0x0073028B
```

- 以上機器碼都是**手算**:一般 Ripes 不認得 custom-0,無法直接組譯 `threshold`。
- 對照列 `add a0, a0, a1` 和 `threshold a0, a0, a1` 的欄位只差 `opcode`(`0110011` → `0001011`),所以兩個機器碼只有最低 7 位元不同(`0x33` → `0x0B`),可用來檢查手算方法。

## C. 指令數比較表(負責:簡嘉佑)

| 項目 | RV32IM baseline(`threshold_branch.s`) | 自訂指令 `threshold` |
|---|---|---|
| 計數方法 | 靜態+動態;Ripes v2.3.0(Windows),Single-cycle(`RV32_SS`),RV32IM | **依規格推算**,沒有在模擬器實際執行(一般 Ripes 不支援 custom-0) |
| 計數範圍 | `threshold:` 到 `ret`(含 `ret`),不含測試用 `main` | 與左欄一致:同樣包成函式 `threshold: threshold a0, a0, a1` + `ret`,含 `ret`,不含 `main` |
| 靜態指令數 | 5 | 2(`threshold`、`ret`) |
| 動態指令數(每次呼叫) | 3(5 組測資皆為 3) | 2(不隨輸入改變) |
| 條件分支數 | 1(`bge`) | 0 |

- 左欄數字來源:`rv32im/count_result.md`(CP2,Ripes GUI 手動執行並截圖)。
- 右欄數字是**依規格推算**,不是模擬器量到的:`threshold` 依規格一條就完成「有號比較 + 寫入 0 或 255」,所以函式內只剩它和 `ret`。
- 比較結果:靜態指令由 5 條減為 2 條、動態指令由 3 條減為 2 條,條件分支由 1 條減為 0 條。省下的是 `bge` 加上 `li` 的比較與選值工作;如果不包成函式、直接在呼叫處使用(不算 `ret`),則只要 1 條。
