# CP1 — C baseline（THRESHOLD）

## 1. 本次目標

完成 THRESHOLD 的 C 參考實作：把 `rs1`、`rs2` 視為 32 位元有號整數，`rs1 >= rs2` 回傳 255，否則回傳 0，並用 12 組測資驗證結果。

## 2. 設計內容

### 函式設計
- 宣告：`int32_t threshold(int32_t rs1, int32_t rs2)`，位於 `instructions/06_THRESHOLD/c_baseline/threshold.h`。
- 實作：`if (rs1 >= rs2)` 成立回傳 255，否則回傳 0（`threshold.c`）。
- 參數用 `int32_t`，因為規格要求有號比較，例如 `-1` 要比 `0` 小。

### 測資設計
測資共 12 組，放在 `instructions/06_THRESHOLD/tests/threshold_tests.md`，分為三類：
- **官方 3 組**（#1–3）：相等、差 1、負數對 0。
- **一般 6 組**（#4–9）：正大於、正小於、兩個 0、兩個負數、負對正、正對負。
- **邊界值 3 組**（#10–12）：`INT32_MAX`、`INT32_MIN` 與其相鄰值。

測資的類型與要求由組員提出，測資內容與預期輸出是在 GitHub Copilot 協助下產生並整理成檔案，預期輸出並非由組員逐筆手算。產生後，我們以 Claude 逐筆核對預期輸出，並用程式實際執行驗證（見第 3 段與第 6 段）。

### 有號與無號比較實驗
為了確認型別選擇的影響，我們在 AI 協助下設計並執行一個實驗：把比較改成 `uint32_t`（同一組位元當作無號數），用同樣 12 組測資重跑。結果 **3 組失敗**：(-1, 0)、(-3, 2)、(2, -3)。

| (rs1, rs2) | 預期 | `int32_t`（正式實作） | `uint32_t`（實驗版） |
|---|---:|---:|---:|
| (-1, 0) | 0 | 0 | **255 ❌** |
| (-3, 2) | 0 | 0 | **255 ❌** |
| (2, -3) | 255 | 255 | **0 ❌** |
| 其餘 9 組 | — | 全部正確 | 全部正確 |

原因是負數的位元在無號下會被當成很大的正數，例如 `-1` 變成 `4294967295`，所以「`-1 >= 0`」被判成立，與規格不符。這說明規格要求有號比較時，型別必須用 `int32_t`，也說明測資要包含「負對正」的組合才抓得到這類錯誤。

實驗程式位於 `instructions/06_THRESHOLD/tests/signed_vs_unsigned.c`，在該資料夾執行：

```
gcc -std=c11 -Wall -Wextra -I../c_baseline signed_vs_unsigned.c ../c_baseline/threshold.c -o signed_vs_unsigned
./signed_vs_unsigned
```

這是我們刻意做的實驗，不是寫程式時意外遇到的錯誤，所以不列為遭遇的問題。

## 4. 遭遇的問題與解法

### 問題一：不會寫函式，誤貼範例（林煉棠）
- **問題：** 一開始不知道怎麼寫 `threshold`，把一個「找較大數」的範例整段貼進函式，結果在函式裡又定義了另一個函式 `larger`，最後還是 `return 0;`。
- **發現：** 檢查後知道 C 不能在函式裡再定義函式，而且範例是回傳 `a` 或 `b`，和本題要回傳 255 或 0 不同。
- **解法：** 只保留一個 `threshold`，用 `if (rs1 >= rs2)` 判斷，成立回傳 255，否則回傳 0。
- **學到：** 範例要先看懂它在做什麼，再換成自己題目的條件與回傳值，不能整段複製。

### 問題二：存檔後多出一個空格（林煉棠）
- **問題：** 在 VS Code 開檔後 `git status` 顯示 `threshold.c` 有修改，但沒有改邏輯。
- **發現：** 用 `git diff` 看到只是第 5 行 `if` 前面多了一個空格。
- **解法：** 用 `git restore` 還原成已推送的版本。
- **學到：** 推送前要用 `git status`、`git diff` 確認實際改了什麼。

### 問題三：不確定哪些輸入算邊界值（羅允辰）
- **問題：** 一開始不確定哪些輸入算邊界值，也不確定負數比較時預期輸出該是 255 還是 0。
- **處理：** 詢問 GitHub Copilot，並參考它對 `-1` 與 `0` 比較的說明，請它協助產生涵蓋相等、差 1、正負數與 `INT32_MAX`、`INT32_MIN` 附近的測資。
- **限制：** 預期輸出並非本人逐筆手算，對有號比較原理的理解目前以 Copilot 的說明為基礎。

### 問題四：電腦沒有安裝 gcc，無法執行測試（羅允辰、簡嘉佑）
- **問題：** 在 PowerShell 執行 `gcc` 顯示「無法辨識 'gcc' 詞彙」，也無法執行測試程式。
- **發現：** 兩人的 Windows 都沒有 C 編譯器；其中一人還把 Bash 指令（`sudo`、`cd /mnt/c/…`）整段貼進 PowerShell，造成更多錯誤。
- **解法：** 改用 `winget install -e --id BrechtSanders.WinLibs.POSIX.UCRT` 安裝 gcc，重開 PowerShell 後用 `gcc --version` 確認，再用 PowerShell 的路徑格式執行。
- **學到：** 先確認工具已安裝，並分清 PowerShell 與 Bash 的指令寫法，一次只貼一行並看結果。

## 5. 白話說明

THRESHOLD 像一個門檻檢查器：拿一個數字和門檻比。如果數字大於或等於門檻就輸出 255，比門檻小就輸出 0。例如門檻是 10，輸入 10 或 12 得到 255，輸入 9 得到 0。負數也要正確比較，所以我們用有號整數，並測試了很大、很小和負數的情況。
